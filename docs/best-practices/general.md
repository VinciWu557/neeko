# 通用工程实践

> 跨语言、跨框架的通用工程实践，适用于 React 与 Rust。

---

## 1. 可读性

- 命名清晰、函数短小（<50 行）、单一职责。

## 2. 魔法数字

- 硬编码常量提取为具名常量 / 枚举。

## 3. DRY / KISS / YAGNI

- **DRY**：重复逻辑出现 3 次以上必须抽象为共享函数/hook/util。
- **KISS**：优先选择最简单的解决方案，不过度设计。
- **YAGNI**：当前不需要的功能不实现，不预留"将来可能用到"的抽象层。

## 4. 无死代码

- 不遗留未使用的导入、变量、分支。

## 5. 失败可解释（跨域惯例）

- **失败证据随错误内联**：抛出的错误必须携带可读的失败原因（对齐 DAP 的
  `"{base} | adapter stderr: {detail}"` 惯例），调用方不必再去别处找证据。
- **长证据按身份可查**：可达 MB 级的长证据（stderr 流、日志）按键存后端、
  按需分页查询，禁止整体塞进单次 IPC / 事件载荷。
- **证据宿主不得是「成功后才有」的对象**：进程 / 会话 / 连接等对象在失败时
  恰好不存在 —— 证据必须锚定在失败前后都存在的身份键上（如 `(project, language)`）。
- **可用性判据必须与消费点同环境、同语义**：探测（`--version`、`command_exists`）
  与真实执行必须共享同一执行环境（target + cwd + env）；「存在 ≠ 可运行」，
  探测失败要么是硬信号（执行不了），要么是证据（记入诊断），不得静默降级。
- **终态文案一次合成**：由进入终态的**写者**合成并存账，事件与快照投影同一份
  字符串；禁止每个读者各自重建（竞态窗口内会拼出互相矛盾的文案）。
